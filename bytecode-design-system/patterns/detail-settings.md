# Detail and Settings Page Patterns

## Detail page

Suggested structure:

```text
PageHeader
├── Breadcrumb
├── Record title
├── Status badge
└── Contextual actions

Overview / key attributes

Detail sections (label-value pairs)

Related records

Activity timeline (when relevant)
```

Use label-value pairs for read-only attributes. Labels are secondary; values carry the primary emphasis. Group related data and avoid rendering every attribute as an undifferentiated list.

## Settings page

Suggested structure:

```text
PageHeader

Settings navigation
└── General
└── Security
└── Notifications
└── Integrations
└── Preferences

Settings content
└── Relevant form or configuration panel
```

Use a secondary navigation when there are multiple settings categories. Keep each settings section focused and explain the impact of sensitive configuration changes.
